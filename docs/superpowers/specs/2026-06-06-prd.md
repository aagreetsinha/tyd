## 1. Overview

Rebuild the UI chrome of teachyourselfdesign.com while keeping Notion as the CMS. The goal is a fast, minimal learning resource hub that feels intentional — not a Notion export.

**Design direction:** Inspired by adhamdannaway.com/design-resources-library and designresourc.es — dark, minimal, single-column, content-first. Improved for our use case: sequential curriculum with progress tracking and orientation cues, not a flat resource library.

**What changes:** Homepage, chapter page wrapper, navigation, progress tracking, cleanup of leftover template code.
**What doesn't change:** Notion content blocks, `react-notion-x` renderer, URL routing, search, ISR.

---

## 2. Goals

| Goal | Success Criteria |
|------|-----------------|
| Minimal, intentional design | No template artifacts; site reflects Aagreet's brand |
| Users understand scope in 10 seconds | Homepage communicates what the curriculum is and how it's structured |
| Users can track progress | Chapter completion persists across sessions; homepage shows it |
| Users know where they are | Every chapter page shows position (Chapter N of 13) |
| Users can move between chapters | Prev/Next at bottom of every chapter page |
| Fast page loads | No runtime API calls for chrome; Tailwind tree-shaken |
| Scalable | New chapters added in Notion auto-appear; no code changes needed |

## 4. Users

**Primary:** Aspiring UI/UX designer. Career switcher or student. Found via Aagreet's social. Returns multiple times over weeks. May be on mobile.

**Journey:**
1. Lands on homepage → decides in 10 seconds if worth their time
2. Scans curriculum → sees what's in each chapter, understands scope
3. Clicks "Start Learning" → begins Chapter 1
4. Follows external links, leaves site to read resources
5. Returns next session → sees which chapters are done, picks up where they left off
6. Works through all 13 chapters over days or weeks

## 5. User Stories

### Homepage
- **US-1:** As a first-time visitor, I see a clear title, tagline, and author name so I understand what this is within 10 seconds.
- **US-2:** As a visitor, I see all 13 chapters listed with a one-line description so I can understand the curriculum scope before clicking anything.
- **US-3:** As a returning user, I see which chapters I've completed at a glance so I can resume from where I left off.
- **US-4:** As a user ready to start, I click the CTA and go directly to the right chapter — Chapter 1 if new, my first incomplete chapter if returning.

### Chapter Pages
- **US-5:** As a user reading a chapter, I see "Chapter N of 13" in the top bar so I know where I am in the curriculum.
- **US-6:** As a user who has gone through a chapter's resources, I click "Done with this chapter" and it marks it complete.
- **US-7:** As a user at the bottom of a chapter, I can go to the next or previous chapter with one click.
- **US-8:** As a user on mobile, the layout works cleanly without horizontal overflow or illegible text.

### Progress
- **US-9:** My progress persists when I close and reopen the browser (localStorage).
- **US-10:** The homepage progress pill updates to reflect my latest state.
- **US-11:** If I complete all 13 chapters, the Done button is replaced by a completion message.

### Sub-Topic Pages
- **US-12:** As a user who clicked into a sub-topic page inside a chapter, I see the parent chapter's position in the top bar.
- **US-13:** On a sub-topic page, there is no "Done" button — I'm not at chapter level.
- **US-14:** I can return to the parent chapter from a sub-topic page via the breadcrumb in the top bar.

### 8.3 Design System — CSS Variables + Tailwind

Industry standard (shadcn/ui convention): design tokens live as CSS custom properties. Tailwind references them — no raw hex values anywhere in components.

**Step 1 — Define tokens in `styles/global.css`:**
```css
@layer base {
  :root {
    --background:       0 0% 7%;      /* #111111 */
    --foreground:       0 0% 100%;    /* #ffffff */
    --surface:          0 0% 10%;     /* #1a1a1a */
    --border:           0 0% 13%;     /* #222222 */
    --muted:            0 0% 33%;     /* #555555 */
    --muted-foreground: 0 0% 53%;     /* #888888 */
    --accent:           74 100% 59%;  /* #adff2f  */
    --accent-foreground: 0 0% 0%;     /* #000000 — text on accent bg */
    --radius:           0.5rem;
  }
}
```

Tokens use HSL channels without the `hsl()` wrapper — this allows Tailwind to compose opacity modifiers (`bg-accent/50`).

**Step 2 — Tailwind config references CSS vars, never raw hex:**
```js
// tailwind.config.js
module.exports = {
  darkMode: ['class', '.dark-mode'],   // matches existing classNameDark: 'dark-mode'
  content: ['./pages/**/*.{ts,tsx}', './components/**/*.{ts,tsx}', './lib/**/*.{ts,tsx}'],
  theme: {
    extend: {
      colors: {
        background:       'hsl(var(--background))',
        foreground:       'hsl(var(--foreground))',
        surface:          'hsl(var(--surface))',
        border:           'hsl(var(--border))',
        muted:            'hsl(var(--muted))',
        'muted-foreground': 'hsl(var(--muted-foreground))',
        accent:           'hsl(var(--accent))',
        'accent-foreground': 'hsl(var(--accent-foreground))',
      },
      borderRadius: {
        lg: 'var(--radius)',
        md: 'calc(var(--radius) - 2px)',
        sm: 'calc(var(--radius) - 4px)',
      }
    }
  }
}
```

**Why this matters:** To rebrand (different accent, lighter dark, etc.) you change one CSS file — not hunt through components. shadcn components also consume these same vars out of the box.

**Critical:** `darkMode: ['class', '.dark-mode']` — without this, all `dark:*` Tailwind utilities silently fail because the existing system uses `.dark-mode` not `.dark`.

### 8.5 `lib/get-chapters.ts`

```ts
export interface ChapterInfo {
  pageId: string    // raw Notion UUID
  title: string     // e.g. "1. Introduction to UI/UX Design"
  index: number     // 0-based, from numeric title prefix
  slug: string      // URL-safe slug from canonicalPageMap
}

export async function getChapters(): Promise<ChapterInfo[]>
```

**Implementation:**
1. Call `getSiteMap()` — already memoized via `pMemoize`, no extra Notion API calls in same build cycle
2. Get root page recordMap: `pageMap[rootNotionPageId]`
3. Get root block content array: `rootBlock.value.content` — these are the direct child block IDs
4. For each ID: look up block, filter `type === 'page'`
5. Extract title from `block.properties?.title?.[0]?.[0]` (Notion rich-text format)
6. Extract numeric index: `parseInt(title.match(/^(\d+)/)?.[1] ?? '99')`
7. Get slug from `canonicalPageMap` (reverse lookup by pageId)
8. Sort ascending by `index`

**Called from:** Both `pages/index.tsx` and `pages/[pageId].tsx` `getStaticProps`.

### 8.6 Content Configuration — Chapter Metadata

Chapter descriptions and any other editorial metadata that can't be pulled from Notion live in a typed content config file. This is the single source of truth for non-Notion content — not scattered strings in components.

```ts
// content/chapters.ts
export interface ChapterMeta {
  index: number
  description: string          // 1–2 sentences shown on homepage under title
  // extendable: estimatedTime, tags, etc. can be added here later
}

export const chapterMeta: ChapterMeta[] = [
  { index: 0,  description: "Get oriented. How to use this guide and what to expect." },
  { index: 1,  description: "What is UI/UX? Core principles and the designer's mindset." },
  { index: 2,  description: "Colour, typography, spacing, and visual hierarchy fundamentals." },
  // … 13 entries total
]

export function getChapterMeta(index: number): ChapterMeta | undefined {
  return chapterMeta.find(c => c.index === index)
}
```

**Rules:**
- All user-facing strings live in this file, never inline in JSX
- The `ChapterMeta` type is the extension point — add fields here (e.g. `estimatedMinutes`, `tags`) without touching components
- Components import `getChapterMeta(index)` — not the raw array

**Aagreet writes these 13 descriptions** before or during implementation. Placeholders are used until provided.

## 9. Coding Standards

### Styling
- New components: Tailwind utilities only. No new CSS module files.
- Existing components: leave CSS modules untouched — no migration.
- `react-notion-x` content area: zero Tailwind classes inside NotionRenderer output.
- All colours via token names (`bg-accent`, `text-muted-foreground`) — never raw hex or hardcoded HSL values in JSX.
- Tailwind directives (`@tailwind base/components/utilities`) added to `styles/global.css`. Immediately test Preflight does not break existing notion styles.
- Content max-width via Tailwind class (`max-w-2xl` = 672px for reading, `max-w-3xl` = 768px for homepage) on wrapper elements, not globally.

### Component Design
- shadcn/ui primitives (Button, Progress, Separator, Sheet) used before building custom.
- Each component has one clear responsibility. No components that both fetch data and render UI.
- Props typed with TypeScript interfaces — no `any`, no untyped props.
- Client-only hooks (`useProgress`, `useDarkMode`) called only in client components; SSR-safe guards in place.

### Content
- All user-facing strings in `content/chapters.ts` — not inline in JSX.
- All design tokens in `styles/global.css` CSS vars — not in components.
- Config values in `site.config.ts` — not scattered across files.

### File conventions
- `lib/` — pure logic, no JSX
- `components/` — React components only
- `content/` — static editorial content (strings, metadata)
- `styles/` — CSS only

## 11. Edge Cases

| Case | Behaviour |
|------|-----------|
| Notion API down at revalidation | Next.js serves stale cached page |
| Chapter added in Notion | Appears in homepage + top bar within 10s ISR |
| Chapter deleted | Disappears from lists; orphaned `tyd_progress` entry is ignored |
| User clears localStorage | Progress reset; treated as new visitor |
| Sub-topic page visited | Top bar shows parent chapter position; no Done button |
| Chapter 0 — no previous | Prev link hidden |
| Chapter 12 — no next, already complete | Shows completion message, no navigation |
| JavaScript disabled | LocalStorage fails silently; content still renders fully |
| `chapters` extraction fails | Fallback: render standard NotionPage without custom chrome |
